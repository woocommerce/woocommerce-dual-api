*** WooCommerce Dual API Changelog ***

= 0.1.0 =
* Initial release: the dual (code + GraphQL) API engine extracted from WooCommerce core (10.9 to 11.1), unchanged in its namespaces, options, filters and hooks.
* Plugin activation replaces the dual_code_graphql_api feature flag; the plugin stays dormant on WooCommerce versions that ship the engine in core.
* The "Endpoint URL" setting is gone with WooCommerce core's proof-of-concept endpoint: every endpoint's route is chosen by the plugin that registers it.
* The builder emits the consuming plugin's text domain into the generated code instead of a hardcoded "woocommerce", ships with the plugin so code APIs can be built against an installed copy, and skips formatting when phpcbf isn't available instead of failing silently.
* Fix unnecessary repeated processing of fragments in the GraphQL side of the dual API.
* Bound the parsed-query cache: queries longer than 16 KB are no longer persisted and the OPcache directory stops growing at 1000 files or 32 MB (all filterable), so unauthenticated callers can't exhaust disk or OPcache memory by sending unique queries.
* Add a "Maximum query length" setting (64 KB by default) that rejects longer queries before they are parsed.
* Add an "Allow anonymous requests" setting (on by default) and a woocommerce_graphql_request_allowed filter that refuse a request right after the principal is resolved, before the query is parsed, cached or validated.
* Strip the "Did you mean ...?" suggestions from validation errors when the caller may not run introspection, since they would otherwise let the schema be enumerated by trial and error.
* Keep query validation proportional to the size of the document: the depth and complexity limits are checked before the other rules, the field-merge rule deduplicates repeated fields structurally and stops with a single error when its comparison budget runs out, and a response carries at most 100 errors. A query of a few kilobytes repeating a field could previously take minutes to validate and return millions of errors, before any authorization check.
